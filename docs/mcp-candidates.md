# Which MCP servers would benefit from a codemode wrapper

Notes written 2026-11-22. They combine three things, and each claim says which one it rests on:

- **Your usage** ([mcp-usage.md](mcp-usage.md), generated by `npm run mcp:usage` from your own Claude Code transcripts).
- **Catalogue shape**: how many tools a server offers, from the tool lists visible in a session. Counts marked "about" were counted by eye.
- **Our measurements** ([../bench/RESULTS.md](../bench/RESULTS.md)): what codemode saved on six services.

## 1. What your transcripts show

The usage report covers **22 saved transcripts (about 165 days)**. It found **no calls to any wrappable MCP service**: the only MCP traffic was `computer-use` (81 calls, one UI step each) and the Claude app's own servers (`ccd_*`). Almost all tool use was `PowerShell`, `Bash`, `Edit`, `Write` and `Read`, which are built-in tools, not MCP.

So the data cannot rank candidates yet. Two reasons to be careful with that: transcripts are only what Claude Code kept (headless `claude -p` runs, such as the benchmark, are not saved), and the connectors you have set up (Notion, Linear, Google Calendar, Gmail, Drive, Context7, Docs) may simply not have been used in these sessions. **Rerun `npm run mcp:usage` after a few weeks of real use** and the table fills in; it needs no changes.

## 2. What the catalogues suggest

Our measurements say the saving comes mostly from two things: **how many tool definitions the model no longer has to carry** (3 tools or 4 tools: about nothing; 16 to 25 tools: 63% to 88% fewer tokens), and **results the script can filter instead of the model reading them** (Filesystem `log-triage`: 118,000 tokens against 5,500). Codemode did not help time: Calendar was 27% to 56% slower because of the extra `get_api` call.

| Server you have connected | Tools (about) | Wrapper today | Verdict | Why |
|---|---|---|---|---|
| Notion (hosted connector) | 85 | `notion/oauth` (hosted, read and write) and `notion/token` (self-hosted) | **Strong** | Largest catalogue; listing and querying pages and databases returns long records |
| Linear | 72 | none | **Strong** | Second-largest; issue and project lists are big and usually filtered afterwards |
| Gmail | not seen | none | **Likely, check first** | Message bodies are large and mostly irrelevant to the question asked |
| Google Drive | not seen | none | **Likely, check first** | Same: long documents, small answers |
| Google Calendar | 9 | none (a CalDAV wrapper was built, measured and removed) | **Weak** | Few tools. The measured calendar saving was real in tokens, but it cost time |
| Figma | 7 | none | **Weak** | Results are large but the model needs them verbatim to write code |
| Context7 | 2 | none | **No** | Two tools: nothing to save. The documentation text is the point |
| Claude Docs | 8 | none | **No** | Part of the Claude app, and edits are one call at a time |
| computer-use | 28 | none | **No** | One UI step per call; every step needs the model to look at the screen |
| Browser (Playwright, or the Chrome extension) | 25 and 17 | `playwright` | **Yes, for scripted work** | Page snapshots are big; interactive exploration is not a good fit |

There are two Notion wrappers. `notion/token` wraps the **official self-hosted server** (24 tools, needs an integration token, sees only pages shared with it); the benchmark numbers come from it. `notion/oauth` wraps the **hosted connector** (77 tools, signs in with OAuth through `npm run login -- notion/oauth`) and offers all of them; calls to tools the server marks destructive are reported after each script, and `CODEMODE_NOTION_READ_ONLY=1` narrows it to the 39 read-only tools. It has not been benchmarked yet, so the Notion numbers are "what codemode does on a Notion-shaped catalogue".

## 3. How to decide, before building one

A wrapper is worth building when most of these are true. The first two matter most.

1. **The catalogue is large**: 15 tools or more, or tool definitions of 5,000 tokens or more. Below about 10 tools the fixed saving is small (our 4-tool Windows run: 3% fewer tokens, 44% more cost).
2. **Results are big and then filtered**: lists, searches, records, pages, where the question needs a few fields. Check for results of 8,000 characters or more (`npm run mcp:usage` counts them).
3. **Calls come in chains** of 3 or more to the same service with no other tool between them.
4. **The data does not need to reach the model verbatim.** If the model has to read the whole result to do the job (documentation, design context), a script cannot help.
5. **An upstream you can run exists** with credentials you control (a self-hosted server, an API token), pinned and lockable. OAuth-only connectors cannot be wrapped yet.
6. **You can test it safely**: a throwaway workspace, a local sandbox, or read-only access (see `docs/production.md`).

Skip it when the tool is a single lookup, when every step depends on seeing the screen, or when the saving would only be the smaller definition on a catalogue of a handful of tools.

## 4. Standing rule (installed in your user-level CLAUDE.md on 2026-11-22)

You asked for a rule that prefers codemode and asks before using direct MCP access where no wrapper exists. It now lives in `~/.claude/CLAUDE.md`, so it applies in every project; the text below is the version before two small additions (the exact current text is in that file). To remove it, delete that section from the file.

```
## MCP tools: prefer codemode wrappers

Before calling a tool from an MCP server, other than the Claude app's own servers (ccd_*, terminal,
visualize, scheduled-tasks, computer-use):

1. Look for a codemode wrapper: run `node C:\repos\codemode\src\cli.ts --list` (one file per service in
   C:\repos\codemode\services). A registered wrapper shows up as tools named mcp__codemode-<service>__execute_code
   and mcp__codemode-<service>__get_api; use those instead of the direct tools.
2. If no wrapper exists for that server, do not call its tools yet. Say which server it is, how many
   tools it has and whether its results are large, and ask whether I want a wrapper built. Go on with the
   direct tools only after I answer.
3. If I say to use the direct tools, do so for that task only.
```

Limits of such a rule: it is guidance the model follows, not enforcement. A stricter version uses Claude Code permission rules (`ask` or `deny` entries for specific `mcp__<server>__*` tools) so the client itself stops before a direct call; that has to be listed per server, because a pattern broad enough to cover every MCP tool would also catch the codemode wrappers.

## 5. Next steps, in order

1. Register the wrappers you want to use: `claude mcp add codemode-<service> -- node C:\repos\codemode\src\cli.ts <service>` (after `npm run servers:install`). `claude mcp list` showed only the claude.ai connectors from this folder.
2. Use Claude normally for a few weeks, then `npm run mcp:usage`, and read it against section 3.
3. Decide on the Linear wrapper first (largest unwrapped catalogue). Open question: whether Linear's hosted server accepts an API key for non-interactive use.
4. Register the wrappers (step 1): the rule tells Claude to stop and ask when a wrapper exists but is not registered.
